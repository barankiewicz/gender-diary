# The Node tier does not import paraglide

`vitest.config.ts` runs plain Node with no `$lib` alias and no SvelteKit plugin, and
`src/lib/paraglide/` is generated by the Vite plugin and gitignored. Any module that
imports `$lib/paraglide/runtime` is unreachable from `npm test`. The split between
`src/lib/data/epochDay.ts`, which imports nothing and is fully tested, and
`src/lib/data/dates.ts`, which imports `getLocale` and has no tests at all, is that
constraint made visible rather than an oversight.

## Why

The Node tier's value is that it runs on every change: 47 tests in 157ms with no
build step and no generated code on disk. Adding a `$lib` alias plus a paraglide
generation step before `vitest` would make the locale-aware modules importable, at
the cost of that property and of a fresh clone being able to run `npm test` before
anything else.

The cheaper seam is the other direction. Anything worth testing gets expressed as
arithmetic over epoch days and lives in the import-free core; the locale-aware
module above it binds `getLocale()` and formats. `setLocale()` reloads the page
(`src/routes/settings/+page.svelte:41`), so the locale is constant for a page's
lifetime and nothing is lost by binding it at one place.

## Consequences

`dates.ts` reads as a pure pass-through if you look at the file alone, because at
one point it was mostly re-exports. It will be proposed for deletion by anyone
reviewing the data tier from the outside - this ADR exists because that suggestion
was made and rejected during an architecture review on 2026-08-11.

Presentation logic that genuinely needs testing does not get there by moving the
test tier. It gets there by moving the arithmetic down into the core and returning
numbers, leaving the locale-aware module with formatting and nothing else. Duration
labels follow the same rule as `scheduleLabel` in ticket 07: the module returns
years, months and days, and the i18n layer supplies the words.
